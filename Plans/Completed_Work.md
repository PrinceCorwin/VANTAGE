### August 20, 2026 (Shared user settings across databases; Schedule Report lookahead headers; P6 stub minimum values)

**Three independent fixes. All build clean (0 errors); not yet UI-confirmed by Steve (the app was running an older build during the session).**

- **User settings are now shared across all local databases.** Grid layouts, saved filters, column width/order/visibility, and every other `UserSettings` value moved out of each project `.db` into a single shared per-machine database `%LocalAppData%\VANTAGE\VANTAGE_UserSettings.db`. Prompted by a field report that switching databases in the new Database Manager reset the user's grid layouts — because `UserSettings` lived inside each `.db`, a switch pointed at a different file with an empty settings table. `SettingsManager`'s five `UserSettings` methods (`GetUserSetting`, `SetUserSetting`, `RemoveUserSetting`, `GetAllUserSettings`, `ImportUserSettings`) now use a new `DatabaseSetup.GetUserSettingsConnection()`; `AppSetting` methods are deliberately untouched and stay per-database, because `AppSettings` holds the per-project sync cursors (`LastPulledSyncVersion`). New in `DatabaseSetup`: `UserSettingsDbPath`, `GetUserSettingsConnection()`, `InitializeUserSettingsSchema()` (creates the shared `UserSettings` table, returns whether the file was just created), and a `UserSettingsDbWasCreated` flag; the shared schema is initialized inside `InitializeDatabase()`.
- **One-time recovery sweep so no existing layouts are lost.** On the first launch after this ships (detected by the shared file not yet existing), `SettingsManager.MigrateUserSettingsToSharedStore()` copies the active database's `UserSettings` wholesale into the shared store, then unions grid layouts (`GridLayouts.*`) and Project-Dashboard report layouts (`ReportLayouts.*`) from every *other* registered database — collision-safe (a same-named layout from another DB is kept as `<name> (<DbName>)`, and the layout's own `Name` is patched to match). Recovers layouts that were stranded in databases the user had switched away from.
- **Behavior change — Reset User Settings is now global.** Because settings are shared, the Reset User Settings dialog now resets preferences for all local databases at once, not just the active one. Expected consequence of the shared store.
- **Schedule Report lookahead column headers now match the selected window.** In `ScheduleReportExporter`, the two lookahead columns were hardcoded to `ThreeWeekStart` / `ThreeWeekFinish` even though the worksheet name already changed with the 3/6/9-week selection. They now read `3WLAStart`/`3WLAFinish`, `6WLAStart`/`6WLAFinish`, or `9WLAStart`/`9WLAFinish` (derived from the existing `lookaheadLabel`). Display-only headers — the importer keys off the `Activities` table, not these strings, so no round-trip impact.
- **P6 New-ActNO stub records no longer land with zero budgets.** In `ScheduleRepository.CreateStubActivitiesFromP6Async`, stubs created from the New ActNOs dialog previously got `BudgetMHs` straight from P6 (often 0), `ClientBudget` unset (table default 0), and `Quantity` = 0.001. Now `BudgetMHs` floors at 0.001 (`Math.Max(c.BudgetMHs, 0.001)`), `ClientBudget` is inserted at 0.001 (added to the local Activities insert), and `Quantity` is 1 (local Activities + Azure `VMS_ProgressSnapshots` inserts). The stub Activity is `LocalDirty = 1`, so the new `ClientBudget`/`Quantity` also propagate to Azure `VMS_Activities` on the next sync push.

**Key files:** `DatabaseSetup.cs`, `Utilities/SettingsManager.cs`, `Utilities/ScheduleReportExporter.cs`, `Data/ScheduleRepository.cs`. **Docs:** `Plans/Completed_Work.md`, `Plans/Project_Status.md`, `Plans/Decisions.md`, `Help/manual.html`.

### August 18, 2026 (VP vs Vtg Report — flexible summary-sheet match + Budget/Earned Delta columns)

**Enhancement to the existing VP vs Vtg Report (`Utilities/VPvsVtgReportAugmenter.cs`). Builds clean (0 errors); not yet UI-confirmed by Steve. (A separate Database Manager feature is also in the working tree from a parallel session — being documented by that session, not here.)**

- **Summary-sheet lookup relaxed.** Previously required a tab named exactly `Summary` and threw "'Summary' sheet not found" otherwise. Now `ResolveSummarySheet` accepts **any tab whose name contains "summary"** (case-insensitive, tolerates extra words/spaces — `Summary Sheet`, `WK 33 Summary`, trailing space all match; first match in tab order wins), then **falls back to `Sheet1`**, and only throws if neither is present.
- **Two new columns — `Budget Delta` and `Earned Delta`** — appended after `Vtg Budget` / `Vtg Earned`. Delta = Vantage minus Viewpoint (`Vtg Budget - Est Hours`, `Vtg Earned - JTD ERN`): **negative = Vantage under Viewpoint, positive = over**. Colored on the **same 1% band** as their source cell (red when the pair is outside tolerance, green within, orange `Not Found` for unmatched rows) so a row never shows a green source cell beside a red delta. Headers are plain ASCII ("Delta", not the glyph — per Steve's no-symbols-in-generated-files rule).

- **Manual updated.** `Help/manual.html` VP vs Vtg Report section now documents all four added columns, the Delta calculation + sign convention, the shared 1% coloring, and a new note explaining the automatic summary-tab detection (any tab containing "summary", else `Sheet1`).

- **Add/edit form** (`Dialogs/TutorialEditDialog`) — Upload mode browses to an `.mp4`, auto-inspects it (codecs, resolution, duration, size) and shows a readout; requires H.264 + AAC and blocks otherwise (the app can't transcode). Edit mode changes just the title/description. Enforces a unique filename and a unique title (case-insensitive; edit mode excludes the item's own title).
- **Video processing** — `Utilities/Mp4Tooling` shells out to ffprobe (inspect) and ffmpeg (`-map 0:v:0 [-map 0:a:0] -c copy -movflags +faststart` — faststart + drops any timecode/data track, no re-encode) before upload, matching the manual DaVinci-export workflow.
- **ffmpeg is NOT bundled in the installer.** `Utilities/FfmpegProvider` lazy-downloads `ffmpeg-tools.zip` (~73 MB) from the tutorials S3 bucket into `%LocalAppData%\VANTAGE\tools\` on the first upload, SHA-256 verified, extracted once — the main installer stays lean and only admins who upload ever fetch it.
- **S3 write methods** added to `Services/TutorialService`: `SaveManifestAsync` (writes via a lowercase-keyed DTO so the runtime-only `Watched` flag never lands in tutorials.json), `UploadVideoAsync` (progress), `DeleteVideoAsync`, `VideoExistsAsync` (authoritative pre-upload orphan-overwrite guard), `ListVideoKeysAsync` (manifest/bucket reconcile), `DownloadObjectAsync`.
- **IAM** — the `vantage-takeoff-user` `TakeoffAppAccess` policy's tutorials statement expanded from GetObject-only to Get/Put/Delete/List (`S3TutorialsReadWrite`). Admin gating: the menu is hidden for non-admins, the handler re-checks `IsAdmin` + Azure connection, and Delete re-verifies `IsUserAdmin` against Azure.
- **Watched-badge cleanup** — `SettingsManager.PruneWatchedTutorials` runs on every Tutorials-library open, dropping watched keys not in the manifest, so a deleted (or later same-name re-uploaded) video never shows a stale "Watched" badge. `Utilities/TutorialKeyValidator` sanitizes the user filename into a safe flat `.mp4` key.
- **Docs** — `Help/manual.html` gained an Administration → Manage Tutorials subsection (+ TOC entry and Admin-menu bullet).
